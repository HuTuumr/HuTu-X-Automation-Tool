# HuTu助手

![Uploading image.png…]()

在 X（Twitter）帖子下面加一个 **AI** 按钮：点一下生成评论草稿，确认后点「回复」自动发出。
模型可以跑在本机（LM Studio / Ollama），也可以接云端 OpenAI 兼容接口。

## 装

1. Chrome 打开 `chrome://extensions` → 右上角打开「开发者模式」→「加载已解压的扩展程序」→ 选这个文件夹。
2. 点浏览器工具栏里的扩展图标，打开设置页。
3. 先让本地模型服务跑起来（下面二选一），再点「测试连接」，模型下拉框会自动出现，然后「保存」。

## 接模型（三选一）

### A. LM Studio（本机）

1. 左侧栏点 **Model Server** → 点 **Start Server**，端口 `1234`
2. 设置页接口地址 `http://127.0.0.1:1234/v1`，点「测试连接」，选模型，保存

命令行也可以：

```powershell
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" server start -p 1234 --cors
```

### B. Ollama（本机）

```powershell
ollama serve
ollama pull qwen3:4b
```

设置页接口地址填 `http://127.0.0.1:11434/v1`，模型名填 `qwen3:4b`，API Key 随便填。

### C. 云端 OpenAI 兼容接口

设置页把接口地址换成服务商的地址、填 API Key、模型名：

| 服务 | 接口地址 | 模型名示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |

⚠️ 用云端时，帖子和生成内容会发到服务商那边，不再是纯本地。

接好之后可以自检一次：

```bat
python selftest.py
```

正常会打印在线模型、耗时和一条样例草稿。

## 用

1. 打开 `x.com/home`，每条帖子操作栏最右边会多一个 **AI** 按钮。
2. 点它 → 右侧面板显示原帖和生成的评论。
3. 不满意点「重新生成」，满意点「回复」——自动定位、填入、发送。

**不会自动走时间线，不会自动滚动，不会自动发送。** 点哪条、发不发，全由你决定。

### 点「回复」为什么现在很快就写完（0.7.2 起）

以前点「回复」到字出现在输入框里要等 1.5–3 秒，全是写死的 `sleep`：滚动后先睡 0.9–1.6 秒、弹框后睡 0.5–0.9 秒、写之前再睡 3 次 0.1–0.2 秒。现在全部改成等真实信号：

- 推文已经在屏幕里就**不滚动、不睡**；不在才滚，滚完立刻继续；
- 回复框一出现（每 40ms 查一次新出现的 `contenteditable`）就开始写，不再固定等 0.5–0.9 秒；
- 写入前只在没聚焦时才点一下输入框，`insertText` 之后每 30ms 验一次文字，写对就走；
- 发送键一变成可点（`aria-disabled=false`）立刻发送，每 30ms 查一次；
- 万一字被页面清掉、发送键一直灰，会自动再写一次再发。

结果：点「回复」到文字进框大约 **0.25–0.45 秒**，再等发送键亮起就点掉。

## 一次一条，不满意就自己点「重新生成」（0.7.0 起）

点一次 AI，只发一次请求、只出**一条**草稿：

- **不会再出现「生成完了又自己重跑一遍，把上一条冲掉」**：模型写什么就显示什么，不做「长度/套话/重复」的静默重跑。只有这次返回的是空内容（真的什么都没生成）才补一次。
- **不满意怎么办**：点「重新生成」，换一个切入角度再要一条；草稿框里的字随时可以手改。
- **不用句号也不用逗号**：提示词里明确要求不出现句号、逗号、顿号、分号，`sanitize()` 里再兜底把 `。，、；,;` 全部删掉，只留问号和感叹号（小数点不动，`3.5万` 不会被破坏）。
- **顺带把长度收紧**：规则里加了「只写一句话，超过 20 字就把后半句砍掉」，因为去掉逗号之后模型容易写成一大串。提示词里也要求只用常用字、写完默读，采样加了 `min_p: 0.05`、温度 0.9 封顶，用来压怪字。
- 想改回一次给两条：`background.js` 里恢复多候选的提示词和 `CANDIDATE_COUNT` 即可（面板的候选卡片 UI 还在，条数 >1 时自动出现）。

## 换模型后一直提示「没写出完整的一句话」怎么办（0.7.1 起）

有些模型（典型是 Google **Gemma 4 E4B**）看到几百字的长规则会先"想"一大段——思考内容走 `reasoning_content` 通道，正文一个字都不剩，几十个 token 全被思考吃掉。另外它吐的第一个 token 常常就是换行，要是请求里带了 `stop: ["\n"]`，会立刻把整条掐成空字符串，表现就是每次点都失败。

现在的处理：

- **请求里不再发 `stop`**，改成拿到结果后自己取第一行，开头多一个换行也不会被掐空；
- **三级兜底**（`background.js` 的 `generate`）：第一次用你原来的完整规则；空输出就换一句**短提示 + 明确禁止思考**再要一次；还空就换个温度再要一次；三次都空才报错，并提示去 LM Studio 关掉思考或换模型；
- 只要拿到内容就原样显示，不会再把好的草稿冲掉。

实测 Gemma 4 E4B：12 次点击 11 次一次成功、1 次走了第二轮，平均 0.5 秒（E4B 本身很快）。

### 0.7.3：思考一开始就掐掉，不再白等

之前即使加了兜底，第一次尝试仍然是"等它把 96 个 token 的思考写完才发现正文是空的"，这一段就白等 1–1.5 秒。现在流式读的时候会盯着 `reasoning_content`：**只要出现思考、正文还是零个字，攒到 24 个字符就直接 `AbortController.abort()` 掐断**，立刻换短提示重来，代价从 1.5 秒降到 0.15 秒左右。同时在完整规则的提示词里加了一句"第一个字就是评论的第一个字，不要输出思考过程"。

面板状态栏现在会带耗时，例如「草稿就绪… · 0.43s」，这个数字是从点击到结果的全程，方便判断慢在哪。

## 速度

一次请求大约 **1.5–2 秒**出结果，**1.1 秒左右**开始出字（本机 27B IQ2_S + RTX 3060）；换成 Gemma 4 E4B 后约 **0.3–0.5 秒**：

- **流式输出**：模型边生成边回传，草稿框逐字长出来，不用等整段结束。
- **输出上限 96 token**：一条 7–20 字，够用；生成量小，显卡风扇最安静。
- 生成完不自动发送，点「回复」才发。

模型侧还有两条（不改代码，只影响 LM Studio）：

- Context Length 调到 4096 就够评论区用，能多留出 1 GB 显存，避免显存满了走 PCIe 交换导致突然卡到十几秒。
- 「Draft MTP / 推测解码」在这个 27B IQ2_S 上命中率只有 3–10%，开不开速度差不多，关掉省显存。

想再快一档只能换模型：RTX 3060 12G 上，27B 的 2 bit 量化大约 20–25 tok/s；换 4B/8B 的 Q4 量化能到 60–90 tok/s，点一下不到 1 秒，中文评论质量反而更稳（2 bit 的 27B 掉智力很明显）。

## 注意

- 生成完草稿后**不会自动发送**，你点了「回复」才算发出去。
- 面板只用来显示状态和暂存最后一条草稿，可以 `⧉` 复制、`⌫` 清空回复框、`–` 收起。
- X 的 DOM 会改版。选择器集中在 `content.js`：`ART_SEL`、`[role="group"]`（AI 按钮注入点）、`[data-testid="reply"]`、`[data-testid^="tweetTextarea_"]`。坏了改这几处。

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 测试连接失败 `Failed to fetch` | 服务没起；或端口不对；LM Studio 没开 CORS |
| 返回 404 model not found | 模型名不对，点「测试连接」重新选 |
| 草稿里出现大段思考过程 | 模型不支持 `/no_think`，把 `maxTokens` 调小或换 instruct 版 |
| 点「发送」后编辑框不消失 | 已在 0.2.0 移除自动发送，此问题不再出现 |
| 输入框里出现几千字重复内容 | 0.1.0 逐字写入的 bug，现已改为整段写入并校验；面板右上角 `⌫` 可手动清空回复框 |
| 推文下面没有 AI 按钮 | 刷新页面；确认是 `x.com` 且已登录；广告/无头像卡片不会注入 |
| 面板不出现 | 刷新页面；确认扩展在 `x.com` 上有权限 |
| 生成的草稿总是很像 | 4B 模型的通病；已在提示词里加「随机角度」和禁开头词，仍重复就调低 temperature 到 0.7 |
| `生成失败：Extension context invalidated` | 扩展被「重新加载 / 更新」过，页面里跑的还是旧脚本，它的 `chrome.runtime` 已作废。**按 F5 刷新页面**即可；0.7.4 起检测到这个错误会提示并自动刷新一次 |
| `Receiving end does not exist` | 后台 Service Worker 刚被系统挂起，0.7.4 起会自动等 300ms 重发一次，通常无感 |
